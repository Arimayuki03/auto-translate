# 沉浸式网页翻译浏览器插件 — 设计文档

> 仿照沉浸式翻译（Immersive Translate），使用自建 AI API（OpenAI 兼容接口）实现网页双语翻译。

> **⚠️ 实现差异说明**（本文为阶段 0 的原始设计，实际实现已演进，关键出入）：
> - **消息协议**：`action:"translate"` → `type:"translate"`；未实现 `sourceLang` / `preserveFormat`；批量协议默认「每行一个译文」，可选 `===IT_SEP===` 哨兵协议（`api.batchMode`）；请求携带 `sessionId`（引擎 generation），还原/换页时 background 按会话中止在途请求
> - **设置模型**：`api.backup`（嵌套）→ `backupApi`（顶层）；`translate` 新增 `viewportLazy` / `contextEnabled` / `contextMaxChars`；`autoTranslate` 默认 `false`；`maxConcurrency` 默认 `2`（v3→v4 迁移）；新增 `minRequestIntervalMs`（请求启动限速间隔，默认 500）、`batchMode`（lines/separator）、`freeEndpoint` / `freeBackupEndpoint`（googlefree 通道端点）；`sensitivePages` 默认 `false`（v3→v4 迁移）
> - **API 格式**：新增 `googlefree`（Google 免费翻译通道，无需 Key；内部固定哨兵协议，支持主/备端点）
> - **存储层**：缓存用 `chrome.storage.local`（非 `session`）；哈希函数 FNV-1a 32 位（非 md5/SHA-256，值携带原文校验防碰撞错译）；缓存写入双层（内存 + 磁盘），内存层软上限淘汰
> - **目录结构**：无 `src/styles/`（样式在 `content.css` / `popup.css` / `options.css`）；`queue.ts` → `translate.ts`；content 层另有 `engine.ts` / `observer.ts` / `ui.ts` / `navigation.ts` / `perSite.ts` / `translate.ts` / `scheduler.ts`
> - **渲染架构**：块级译文用 `.it-wrap` 包裹原容器（非原文下方插 `<div>`）；仅译文模式为 `textContent` 原位替换（保留元素结构）；列表/表格项退回内部插入；行内标签用 `container.after()` 兄弟插入；占位为骨架屏呼吸块（非不可见），高度按目标语言估算 + 真实行高
> - **UI**：工具条为可拖拽的红色小圆圈 FAB（非顶部条）；段落级翻译按钮已移除；译文灰字无背景、无边框，灰度从页面文字色派生（自适应明暗）；无 Shadow DOM 隔离（仅类名前缀 `.it-*`）
> - **未实现**：流式输出、`requestIdleCallback` 调度、段落局部翻译按钮（悬停翻译，见 docs/未来方向.md 路线图）、划词快捷键触发、iframe / Shadow DOM 内翻译

## 1. 项目概述

一个基于 **Manifest V3** 的 Chromium 浏览器扩展，在浏览网页时自动将页面内容翻译为目标语言，并默认采用"双语对照"模式（原文保留，译文高亮显示在其下方），支持整页翻译、划词翻译、输入框翻译等能力。

### 核心目标
- 网页全文翻译（段落级双语对照 / 仅译文 / 原文模式）
- 划词翻译（选中文本后弹出气泡显示译文）
- 输入框翻译（在搜索框 / 输入框中快捷翻译已输入内容）
- 自定义 AI API：用户自备 BaseURL / API Key / 模型名称（支持 OpenAI/Claude/Gemini/Ollama 四种格式 + googlefree 免费通道）
- 译文缓存（双层：内存 + chrome.storage.local 持久化），跨会话复用节省 API 费用
- 无感体验：自动翻译不弹提示/无闪烁/不打断阅读

## 2. 技术选型

| 项 | 选择 | 说明 |

## 3. 功能需求

### 3.1 页面全文翻译（核心）
- 自动识别网页正文，按段落（p、li、h1-h6 等块级标签）切块
- 翻译前先插入骨架屏占位（按目标语言估算译文高度 + 真实行高，opacity 呼吸动画），翻译完成后原位填充，减少页面跳动
- 三种显示模式：
  - 双语对照（默认）：原文下方插入译文块，译文灰字无背景/无边框
  - 仅译文：原文文字原位替换为译文（保留元素结构与链接，样式不变），译文元素隐藏
  - 原文模式：一键恢复原始页面，隐藏所有译文元素
- 页面可拖拽红色小圆圈 FAB（点击展开翻译面板）：模式切换、目标语言、翻译/还原、复制译文
- 对已翻译内容不重复翻译（DOM 标记 `data-it-src` / `data-it-processing`）

### 3.2 划词翻译
- 监听 `mouseup`，选中文本后弹出气泡卡片显示译文（设置中可开关）
- 气泡可拖动、可复制译文、可关闭

### 3.3 输入框翻译
- 在 `input` / `textarea` 内容可编辑区域提供翻译按钮
- 将输入内容翻译后替换或插入到输入框，便于跨语言交流

### 3.4 PDF 翻译（后续迭代）
- 优先使用浏览器内置 PDF 阅读器，将文本层映射到内容脚本翻译
- 复杂版式不追求还原，保证文字可读

### 3.5 设置页（Options）
- API 配置：BaseURL、API Key、模型、温度、超时时间
- 翻译设置：目标语言、显示模式、自动翻译开关、翻译触发方式
- 站点黑白名单：白名单模式仅翻译指定站点（省额度）；黑名单站点永不翻译
- 缓存管理：查看/清空缓存
- 敏感页面保护：银行 / 登录 / 支付页面默认不翻译
- 数据导出 / 导入（配置迁移）

### 模块职责
- **content script**：注入页面，负责 DOM 提取、译文渲染、交互（工具条/气泡/按钮）。页面上下文隔离，不直接发网络请求。
- **background service worker**：唯一网络出口。接收 content script 的翻译请求，负责限流、重试、缓存、批量合并请求，防止页面里同时发起大量请求打爆 API。
- **popup**：快速开关翻译、切换模式、进入设置。
- **options**：完整设置页，配置 API 与偏好。

### 消息协议（runtime messaging）
```ts
type TranslateRequest = {
  type: "translate";
  id: string;
  texts: string[];          // 批量文本（同一批次一起发）
  targetLang: string;
};

type TranslateResponse = {
  id: string;
  ok: boolean;
  results?: string[];        // 与 texts 一一对应
  error?: string;
};
```

## 5. 翻译引擎设计（content script 核心）

### 5.1 文本节点提取
- 使用 TreeWalker 遍历 DOM，收集**叶子文本节点**
- 过滤规则：
  - 跳过 `script`、`style`、`noscript`、`iframe`、`svg`、`code`、`pre` 等标签
  - 跳过空白文本（`text.trim().length === 0`）
  - 跳过已翻译标记（`data-it-src`）
  - 跳过长度小于阈值（如 2 字符）的碎片文本，减少请求量
- 对相邻叶子节点做**块合并**：同段落内多个文本节点合并为一个翻译单元，保证句子完整

### 5.2 分块与句切分
- 单次翻译单元过长时按句子切分（正则匹配 `。！？.!?…；;` 等），每块控制在约 1200 字符（默认 `blockMaxChars`）
- 块之间建立映射表 `{ originalText → nodeRefs[] }`，译文回来按位置回填

### 5.3 双语渲染
- 对每个翻译单元，使用**包裹原块**策略（`.it-wrap` 顶替原元素在布局中的位置）：
```html
<!-- 包裹方式（块级容器，如 p/div/h1 等）：wrap 顶替原容器位置 -->
<div class="it-wrap" data-it-unit="it-123">
  <p class="it-orig">原文内容</p>
  <span class="it-translated it-done" data-it-unit="it-123">
    <span class="it-chunk">译文第一段</span>
    <span class="it-chunk">译文第二段</span>
  </span>
</div>

<!-- 内部插入（表格/列表项 li/td 等）：译文附在容器内部 -->
<li data-it-src data-it-inside>
  原文内容
  <span class="it-translated it-done" data-it-unit="it-456">
    <span class="it-chunk">译文</span>
  </span>
</li>

<!-- 行内（链接/折叠摘要等紧凑标签）：译文作为兄弟跟在后面 -->
<a href="..." data-it-src>原文链接</a>
<span class="it-translated it-inline it-done" data-it-unit="it-789">· 译文链接</span>
```
- 仅译文模式：`textContent` 原位替换原文文字（保存原始 innerHTML 到 `data-it-orig-html`），保留元素结构与链接，译文元素添加 `it-translated-hidden`（`display: none !important`）
- 还原：恢复 `data-it-orig-html` 中的原始 HTML，移除全部注入元素与属性

### 5.4 渐进式渲染
- 翻译前按字符数估算占位高度（`minHeight`），不可见占位，翻译完成后原位填充消除跳动
- 使用 `IntersectionObserver`（设置页 `viewportLazy` 开关）：开启时只翻译视口附近的内容（提前 300px 预译），滚动到哪译到哪；关闭时整页直译
- 优先翻译视口内内容，视口外延后处理

### 5.5 与页面样式隔离
- 所有注入元素的类名使用 `.it-*` 前缀，CSS 变量使用 `--it-*` 前缀
- `overflow-anchor: none` 防止译文被浏览器选为滚动锚点
- 译文继承页面字体/颜色/行高（`color: inherit` 等），融入站点风格

### 5.6 无感翻译策略（核心体验）
- **零打扰**：自动翻译不弹横幅、不弹气泡、不打断阅读，状态仅体现在 FAB 上的状态文字
- **无闪烁**：译文块透明度过渡淡入（`it-fade-in` 动画）；插入前按字符数估算占位高度
- **视口优先**：优先翻译视口内内容，视口外通过 IntersectionObserver 延后；MutationObserver 防抖 300ms 检测新增内容
- **失败静默**：翻译失败仅在该译文块显示轻量错误标记，不弹窗，可点击重试；仅译文模式下错误元素自动隐藏
- **防重复**：`data-it-src`（已译）/ `data-it-processing`（翻译中）DOM 标记，绝不重复请求

## 6. AI API 接入设计（background 核心）

### 6.1 多格式支持
插件通过**适配器层**支持多种 API 格式，设置页选择格式后自动适配请求/响应结构，翻译协议（批量拼接、提示词）各格式通用：

| format | 适配服务 | 端点 | 鉴权 |
| --- | --- | --- | --- |
| `openai`（默认） | OpenAI 兼容系（DeepSeek / OneAPI / vLLM / 中转） | `POST {baseURL}/chat/completions` | `Authorization: Bearer` |
| `anthropic` | Anthropic Claude / 兼容系 | `POST {baseURL}/v1/messages` | `x-api-key` + `anthropic-version` |
| `gemini` | Google Gemini | `POST {baseURL}/v1beta/models/{model}:generateContent` | `?key=` 查询参数 |
| `ollama` | Ollama 原生 | `POST {baseURL}/api/chat` | 无 |

### 6.2 默认格式请求示例（OpenAI 兼容）
```http
POST {baseURL}/chat/completions
Authorization: Bearer {apiKey}
Content-Type: application/json

{
  "model": "{model}",
  "messages": [
    { "role": "system", "content": "你是专业翻译引擎，将用户输入翻译为{目标语言}，只输出译文，不要解释。" },
    { "role": "user", "content": "请逐行翻译以下内容，每行一个译文，保持顺序，不要编号，不要任何额外文字：\n{拼接后的原文}" }
  ],
  "temperature": 0.3,
  "stream": false
}
```

### 6.3 批量合并
- content script 同时提交的多个段落（每个段落的句子分块）在 background 合并为一次请求，大幅降低请求次数（批量越大，重复携带的「系统提示词 + 页面上下文」开销越小）
- 双协议（`api.batchMode`）：默认逐行（与历史版本兼容，第三方中转兼容性最好）；可选哨兵 `===IT_SEP===`（段落含换行时更可靠）；googlefree 通道内部固定哨兵协议
- 三级降级：整批解析失败 → 拆 ≤8 段小批量重试（仅「响应正常但解析失败」触发，API 报错不放大）→ 仍失败的组才逐段。最坏情况请求数从 N 压到约 N/8
- 批量响应优先按哨兵分段，缺失时按行匹配（模型加编号时自动剥离「数字. 」前缀）；原文本身含哨兵字符串时强制逐行，避免切错段

### 6.4 可靠性
- **限流**：双层——令牌桶控制「请求启动速率」（相邻请求最小间隔 `minRequestIntervalMs`，默认 500ms ≈ 2 请求/秒，设置页可调）+ 信号量控制并发（默认 2）；429 时全队列冷却（尊重服务端 Retry-After，无头时 1s），恢复后只放行 1 个探针请求
- **重试**：网络错误 / 5xx / 429 指数退避 + 抖动重试（最多 3 次，封顶 60s）
- **超时**：默认 60s，AbortController 中断
- **会话取消**：翻译请求携带 `sessionId`（引擎 generation），用户还原 / SPA 换页时 content 发 `cancel-translation`，background 按 session 批量 abort——在途 fetch 立即打断，中止不触发重试/备用切换/失败上报
- **错误分级**：网络错误/超时/限流/5xx 可重试；4xx 认证/路径错误不重试，直接提示用户检查配置；错误带脱敏诊断（provider/端点主机/状态码/错误码，绝不含 Key），端到端透传到工具条可复制
- **主备切换**：主 API 失败（且错误可重试）时自动切换备用 API（如有配置），同样享受重试策略；googlefree 通道另有主/备端点互切

### 6.5 缓存
- 缓存键：`it-cache:` + `FNV-1a 32 位(targetLang + "|" + text)`
- 缓存值为 `{src: 原文, val: 译文}`：读取时校验原文一致才返回——32 位哈希碰撞时只导致一次未命中重译，绝不把 A 文本的译文当 B 的返回；历史纯字符串条目兼容读取
- 空译文不写入（避免永久命中空串）；写入失败（配额超限）不影响翻译主流程
- 双层缓存：内存（快速层，FIFO ≤5000 条）+ `chrome.storage.local`（磁盘持久层，跨会话复用）
- 内存到达上限时淘汰最旧条目（磁盘不淘汰，待用户手动清空；TTL 过期清理见 docs/未来方向.md）
- 设置页可一键清空全部缓存（内存 + 磁盘）

## 7. 设置数据模型（chrome.storage.local）

```ts
interface Settings {
  version?: number;               // 设置结构版本（迁移用）
  api: {
    format: ApiFormat;            // "openai" | "anthropic" | "gemini" | "ollama" | "googlefree"
    baseUrl: string;
    apiKey: string;               // 落盘前混淆加密
    model: string;
    temperature: number;          // 默认 0.3
    timeoutMs: number;            // 默认 60000
    maxConcurrency: number;       // 默认 2
    minRequestIntervalMs?: number;// 请求启动限速间隔，默认 500（设置页可调，钳制 50–10000）
    batchMode?: BatchMode;        // 批量协议："lines"（默认） | "separator"
    freeEndpoint?: string;        // googlefree 主端点（留空用内置公开端点）
    freeBackupEndpoint?: string;  // googlefree 备用端点
  };
  backupApi?: ApiConfig;          // 备用 API（顶层，非 api.backup）
  translate: {
    targetLang: string;           // 默认 "zh-CN"
    displayMode: DisplayMode;     // "bilingual" | "translated" | "original"
    autoTranslate: boolean;       // 默认 false（手动触发）
    autoDetectSource: boolean;    // 默认 true（配置项，实际由目标语言启发式判断跳过）
    minTextLength: number;        // 默认 4
    blockMaxChars: number;        // 默认 1200
    translateOnSelect: boolean;   // 划词翻译开关，默认 true
    translateInput: boolean;      // 输入框翻译开关，默认 true
    viewportLazy: boolean;        // 视口懒翻译开关，默认 true
    terminology: string[];        // 术语表（⟦n⟧ 占位保护）
    contextEnabled?: boolean;     // 页面上下文注入开关，默认 true（仅整页翻译携带）
    contextMaxChars?: number;     // 标题/描述/正文摘要合计上限，默认 3000
  };
  sites: {
    whitelist: string[];          // 白名单：非空时仅这些域名翻译
    blacklist: string[];          // 黑名单：永不翻译
  };
  security: {
    encryptApiKey: boolean;       // 默认 true
    sensitivePages: boolean;      // 默认 false（v3→v4 迁移后关闭）
  };
  cache: {
    enabled: boolean;             // 默认 true
    maxEntries: number;           // 默认 5000
  };
}
```

## 8. UI/UX 设计

- **红色小圆圈 FAB**（页面悬浮，可拖拽，位置记忆）：点击展开面板 → 翻译按钮、模式切换、语言选择、复制译文、状态文字、收起
- **译文块样式**：译文灰色文字（灰度从页面文字色派生，深浅页面自适应）、无背景、无边框，融入页面风格；多 chunk 译文流式拼接为自然段；段落间距与原文一致
- **划词气泡**：跟随选区定位，带 loading / 失败重试 / 复制状态
- **popup**：快捷 API 配置 + 测试连接 + 当前站点加入黑白名单
- **options 页**：API 配置（主/备用）、翻译设置、站点黑白名单、缓存与数据管理、「测试连接」按钮

## 11. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 页面动态内容（SPA 路由切换） | MutationObserver 监听 DOM 变化 + pushState/replaceState 补丁 + URL 轮询兜底 |
| 长文分块导致上下文丢失 | 分块时按句子边界切分；LLM 可处理部分上下文 |
| 自建 API 并发/速率限制 | 信号量限流 + 批量合并 + 指数退避 |
| 译文回填错位（原文被修改） | 回填前校验容器仍挂载；DOM 标记防重复翻译 |
| 样式冲突 | 类名前缀 `.it-*` + CSS 变量 `--it-*`，继承页面字体/颜色融入站点风格 |
| API Key 泄露风险 | 仅存本地 + XOR 混淆落盘；README 提示自建 API 务必开鉴权 |
