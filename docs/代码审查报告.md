## 一、结论

项目整体质量良好：限流设计（令牌桶 + 429 队列级冷却 + Retry-After + 抖动退避）正确回应了 E-005 封号问题；错误诊断链路（ApiError → withErrorSource → 脱敏 diagnostic → 工具条）端到端完整；buildApiUrl 重叠路径去重、isExcluded 双层记忆化、splitBatch 三级兜底、观察器自突变过滤等细节质量高；测试是回归导向的，正好锁住重构最容易回退的点。

但审查发现 4 个 P1 级真实 Bug（其中 2 个影响用户可见行为）、3 个 P2、若干 P3。以下逐项列出问题、根因与修复状态。

## 二、P1（优先修复，均已修复）

### F-1 googlefree 默认逐行协议下批量必然解析失败，请求量翻倍 ✅ 已修复

- **现象**：选择 Google 免费通道（默认 `batchMode: "lines"`）时，每次全页翻译先打一次注定失败的批量请求（内部 N+1 次 Google 调用），再降级逐段重发 N 次，请求量翻倍。
- **根因**：逐行协议的 user 内容以指令行「请逐行翻译以下内容…」开头（`translate.ts:58`），而 `googlefree.ts` 的 `extractSegments` 在非哨兵模式下按行拆分整个 user 内容——指令行被当成第 1 个待译段发给 Google，输出比输入多一行 → `splitBatch` 段数不匹配 → 整批作废。
- **关键矛盾**：`shared/types.ts` 与《后续任务.md》都约定「googlefree 内部固定使用安全哨兵协议（provider 会忽略 batchMode）」，恢复逐行默认时该约定在代码中丢失；且 `providerRequests.test.ts` 对 googlefree 批量行为零覆盖。
- **修复**：`callApi` 对 `api.format === "googlefree"` 的通道强制 `separator` 协议（与文档约定一致）；新增 `providerRequests.test.ts`「Google 免费通道」用例锁定：请求不含逐行指令前缀、批量解析成功。

### F-2 还原/换页时在途状态清理不完整 → 重新翻译永久缺段 ✅ 已修复

- **现象**：翻译进行中点「还原」再点「翻译」，正在翻译中的段落在刷新页面前永远拿不到译文。
- **根因**（两个口径都漏）：
  1. `fetchBatch` 完成时把文本写入 `doneTexts`，不检查 generation——`restore()` 已清空的集合被在途请求回填，重新翻译时这些文本被 `doneTexts.has(u.text)` 过滤掉；
  2. 在途批次的 `renderBatch` 永远不执行，容器上的 `data-it-processing` 残留，而 `translateAll` 与观察器都会跳过带该属性的容器；`renderer.restore()` 不清理该属性。
- **修复**：`fetchBatch` 写 `doneTexts` 前校验 generation（过期批次删除 pendingTexts 并返回 null）；`restore()` / `resetForNavigation()` 统一移除 `[data-it-processing]`；新增 `sessionCancel.test.ts` 用例：还原时在途批次完成 → 不污染 doneTexts、无残留标记、重新翻译可覆盖。

### F-3 会话取消没有接线到 fetch，「中止在途请求」实际不成立 ✅ 已修复

- **现象**：`cancel-translation` 只能阻止尚未开始的请求；在途 HTTP 请求照常跑完，`withRetry` 的退避 sleep（最长 60s）也不被打断，额度照常消耗。与代码注释/文档声称的「按会话批量中止在途请求，避免浪费额度」不符。
- **根因**：`AbortController.signal` 只在 `translate()` 的几个边界点做布尔检查，从未传入 `postJson` / `gTranslate`，fetch 用的是各自的超时 controller。
- **修复**：`ChatOptions` 增加 `signal`；`postJson` / `gTranslate` 把会话 signal 桥接到超时 controller（`addEventListener("abort")`），中止时抛普通 `Error("cancelled")`（非 ApiError，不触发重试/备用/失败上报，最终仍归一化为 `TranslationCancelledError`）；全部 provider 透传。新增用例锁定「会话中止打断在途 fetch」。

### F-4 译文缓存 32 位哈希碰撞会静默返回错误译文 ✅ 已修复

- **现象**：`cache.ts` 用 FNV-1a 32 位哈希做缓存键，注释称「最坏情况只是缓存未命中」——不成立：碰撞意味着 A 文本命中 B 文本的译文，且磁盘层 key 永不淘汰，长期积累几万条时生日碰撞概率可观（约 5 万条即 25% 期望碰撞对）。
- **修复**：缓存值改为 `{ src, val }` 结构，`get` 时校验原文一致才返回（不一致视为未命中并清除）；历史纯字符串条目按原样兼容（随时间自然淘汰）；空译文不写入缓存（`cache.set` 守卫）。新增 `cacheSettings.test.ts` 用例：碰撞时未命中、空译文不入缓存。

## 三、P2（已修复）

### F-5 observer 早退路径不清 addedRoots → 长期内存泄漏 ✅ 已修复

- `observer.ts` `run()` 的所有早退路径（`document.hidden` / 敏感页 / 子页禁用 / `state === "off"`）都在消费 `addedRoots` 之前返回；翻译关闭时挂在动态页面（聊天、feed 流）上，新增节点被 `addedRoots` / `addedRootsSeen` 强引用无限积累（含已脱离 DOM 的子树）。
- **修复**：`addedRoots` 设上限 FIFO（`MAX_PENDING_ROOTS = 300`，超限丢弃最老的根，保留「激活后补扫」语义）；`addedRootsSeen` 改用 `WeakSet`（脱离 DOM 的节点可被 GC，不阻碍回收），并在消费时与 roots 同步删除，保证节点重新插入 DOM 时仍会被补扫。

### F-6 点击触发的全量扫描是同步的 ✅ 已修复

- `observer.ts` 点击探测兜底（`roots.length === 0`）对 `document.body` 跑一次同步 `extractUnits`（不走 chunked、样式缓存每次重建）。大页面每次点击都有可感的主线程占用，与 E-002 同源但量级小。
- **修复**：兜底全量扫描改用时间片版 `extractUnitsChunked`（逻辑一致、每 12ms 让出主线程）；增量路径（新增子树，通常很小）保持同步版。

### F-7 Anthropic 批量输出预算 4096 写死 ✅ 已修复

- `anthropic.ts` `max_tokens: 4096` 写死，批量（最多 60 chunk）长文本可能被截断 → 解析失败 → 逐段降级（能自愈但浪费整批请求）。
- **修复**：输出预算随输入长度放大（`min(8192, max(4096, 输入字符数/2))`）；部分模型（如 claude-3-haiku）输出上限恰为 4096，被 400 拒绝（`bad_request` 且消息含 max_tokens）时自动降回 4096 重试一次——对所有模型严格不劣于原行为。

## 一、结论

架构与并发防护（代次失效、三级批量降级、按通道限速、Shadow DOM 样式注入）保持高水准；未发现 P0。本轮发现集中在三个面：MV3 生命周期（SW 空闲回收）、SPA/hash 边界场景、交互细节与导入健壮性。以下各项均已在本轮修复并补测试。

## 二、P1（均已修复）

### G-1 SW 空闲回收可打断长翻译 ✅ 已修复

- 整批 LLM 请求（超时上限 120s）与流式首 delta 前的静默生成期既不是扩展 API 调用也没有 Port 消息，worker 空闲 30s 可能被回收，sendResponse 通道随之中断、整批结果丢失。
- **修复**：新增 `src/background/keepAlive.ts`（引用计数 + 每 20s 一次 `chrome.runtime.getPlatformInfo()` 重置空闲计时器）；`translate` 消息处理与划词流式 Port 的整个在途期间挂起，最后一个请求结束后停止（不留悬挂定时器；无 runtime 的单测环境自动跳过）。

### G-2 同页锚点跳转被误判为 SPA 换页 ✅ 已修复

- 已译页面点击 `#toc` 类锚点（或 hash 浅层变化），URL 轮询/pushState 检测发现 href 变化即 `resetForNavigation()`：整页译文闪回原文并重译，浪费 token。
- **修复**：`navigation.ts` 对比去 hash 后的 URL，仅 pathname/search 变化才算换页；hash 路由真正换内容时 `<body>` 替换（force）与 mutation 增量路径照常兜底。

### G-3 气泡内滚动会关闭气泡 ✅ 已修复

- `window` 捕获阶段 scroll 监听会收到 `.it-bubble-body`（overflow:auto）的滚动事件，长译文一滚气泡即消失。
- **修复**：`bubble.ts` 回调判断 `bubble.contains(e.target)` 时跳过。

### G-4 SPA 换页打断在途翻译后 state 永久卡在 translating ✅ 已修复

- 在途批次因代次校验提前 return（不走 `afterGroup`），`resetForNavigation` 不重置 state；新页敏感或标签页在后台（navTimer 跳过重译）时工具条「翻译/还原」按钮永久禁用。
- **修复**：`engine.ts` `resetForNavigation` 末尾兜底：state 为 translating 时置回 `done`——保留「翻译态」语义（SPA 重译判定 `state !== "off"` 依然成立），同时解除按钮禁用。新增回归测试锁定。

### G-5 域名匹配「互为子域名」语义过宽 ✅ 已修复

- `matchesDomain` 的 `d.endsWith("." + host)` 方向使黑名单条目 `a.example.com` 封禁整个 `example.com`，白名单同理放大授权（白名单一个子域等于放行整个主域）。
- **修复**：收紧为单向（host === d 或 host 是条目的子域），并在注释中写明理由。

## 一、悬停翻译判定区域重写（L-1）

- **症状**：鼠标在页面上移动，「译」角标到处冒——旧判定从 `e.target` 向上找最近块级候选（含 div/section 兜底），页面任意位置（空白、卡片内边距、侧栏）几乎都能命中某个装着 ≥20 字符的 div，角标钉在大容器左上角随之乱跳；快速划过文本时角标逐块闪烁。

## 三、仅译文模式部分句子漏翻译（L-3）

# 第八轮审查（第七轮修复复核 + 审查中即时修复，2026-09-17）

> 审查范围：第七轮四项修复（hover.ts 判定重写 / options backupFree / extractor 链接锚定 / 图标字体排除）逐行推演 + 边界组合（dwell × mouseout/划词/滚动/点击、链接拆分 × 仅译文/双语切换/单元素还原、图标判定 × shadow/嵌套、microsoft 备用 × storage 校验/test-connection/运行时降级）。
> 基线验证：typecheck ✅ / lint ✅ / 测试 36 文件 367 用例 ✅ / build ✅。

## 一、审查中发现并当场修复

### M-1 停留计时（dwell）两处泄漏 + 锚点过期 ✅

- **泄漏 1（P2，用户可见）**：dwell 期间 `current` 为 null，`onMouseOut` 第一行就 return——鼠标在文字上停了 200ms 后划走（乃至移出浏览器窗口），250ms 到期角标**照样弹出**，且 `pending` 不清导致弹出锚点停留在早已离开的位置。表现为「我没停但它自己冒出来了」，恰好复刻本轮要消灭的症状。
- **泄漏 2（P3）**：划词选择开始时原实现只 `return`（不出新角标），但**已显示的角标不收起、在途 dwell 不取消**——用户按住拖选时角标钉在原地。
- **锚点过期（P3）**：同一候选 dwell 续计时期间命中行矩形不更新，停留期间布局变化（图片加载/字体切换/动态插入）会让角标弹在旧位置。
- **修复**（`hover.ts`）：`onMouseOut` 先处理 pending 作废（relatedTarget 仍在候选/角标内则保留），再走既有延迟隐藏；划词选择分支从「不出新角标」改为 `hide()`（同时收旧角标与取消 dwell）；同候选续计时时刷新 `pending.anchor` 为最新命中行。
- **测试**：新增 2 例（dwell 中移出不弹 / 划词开始收起角标），红绿验证（修复前 M-1 泄漏 1 用例如期失败）。

### M-2 行内链接单元的仅译文标记残留（疑点证伪，无改动）✅

- 推演怀疑：`<a>` 独立成单元后 `data-it-inplace`/`data-it-orig-text` 打在 `<a>` 上，`clearTranslatedMode` 按 `getSourceTarget` 清理能否全覆盖。
- 验证：临时探针用例走「translateAll → 切仅译文 → 切回双语 → 整页 restore」全链路，`<a>` 上三标记均清空、原文完整恢复——`clearContainer`/`clearTranslatedMode` 按 target 查标记的设计已覆盖链接锚定形态。探针转正为常规口径不合算（与 displayMode 现有 12 例高度重叠），未保留。

## 二、其余推演结论（无改动）

- **microsoft 备用（L-2）全链路核对**：`SUPPORTED_FORMATS` 含 microsoft（storage 校验/导入均放行）；下拉框本就有该选项；`runTestConnection` 与 background `testConnection` 对免费通道都不要求 baseUrl；两个免费 provider 实现不读 `baseUrl` 字段——运行时降级（`freeSiblingApi` 之外的备用路径）对 microsoft 备用完全可用。
- **图标字体判定**：`getComputedStyle` 在 jsdom 返回空 fontFamily → 恒 false（有 try 兜底）；真实浏览器下 cached 后每次提取仅一次正则。`isProtected`（渲染层）与 `isSelfExcluded`（提取层）同口径，仅译文替换不会穿透图标子树。已知取舍：正文里真实的 Material Icons 文字（如文档站演示代码块外仍有少量）会被跳过——与「图标碎掉」相比是正确取舍，且 `CODE/PRE` 本就排除。
- **链接锚定语义变化确认**：`<a>` 永远锚定自身后，块容器单元文本不再含链接词（`"Read the docs for more info"`），翻译上下文略变短；`SOURCE:DOC` 类同一文本去重键变化属于缓存键自然演化（旧缓存自然失效，无错误命中）。`isStandaloneLink`/`NAV_PARENT_TAGS` 已无残留引用。
- **dwell 与 restore 竞态**：dwell 到期回调内重新走 `isEligibleCandidate`（敏感页/整页状态/引擎口径全查），「停留期间被还原」不会弹出「译」角标；restore 分支复查 `data-it-src`/`processing`。
