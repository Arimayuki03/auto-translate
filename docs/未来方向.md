## 一、定位差异——先说清楚不追什么

read-frog 的定位是「AI 语言学习产品」：文章分析、词句讲解（CEFR 分级）、生词本（Notebase）、TTS 朗读、账号体系、数据分析。我们定位是「轻量纯翻译工具」。

**不学它的**：React/Jotai/TanStack 技术栈、monorepo/nx/changesets 工程链、账号与激活体系、行为分析、sidepanel。这些是团队产品化的配置，照搬只会丢掉我们「单文件、零依赖、秒加载」的差异化优势。我们的目标不是变成 read-frog，而是**把一个轻量翻译工具的核心体验做到不输它，同时保留它没有的轻量与可控**。

## 三、小而美的借鉴项（低成本，先做）

这些是 read-frog 里「几十行就能搬过来」的点子：

1. ✅ **缓存 TTL + 定期清理**（已完成，见 P0 一揽子）。
2. ✅ **批量超时按字符数缩放**（已完成：`base + 15ms × 字符数`，封顶 120s）。
3. ✅ **跨标签页请求去重**（已完成：文本+语言在途去重，等待者不随属主会话中止而失败）。
4. ✅ **巨型段落拆分**（已完成：提取阶段按句子边界均衡拆 chunk，中文句读必切、英文 `3.14`/`e.g` 不误切）。
5. ✅ **`{{NO_TRANSLATION_NEEDED}}` 哨兵**（已完成：LLM 批量免译显式回哨兵，解析严格相等映射回原文；免费通道解析兜底）。
6. ✅ **视口优先调度**（2026-09-14 落地）：`translateUnits` 内批次按「距视口距离」动态出队
   （每次出队前按当前视口重选最近的批，滚动后未发批次跟随用户位置），先完成的批先渲染
   （消除队头阻塞）；并发度仍由 FETCH_WINDOW 钳制。jsdom/rect 全 0 环境退化为 DOM 顺序。

### P1：体验增强 —— ✅ 主体已全部落地（2026-09-14 并行一揽子），剩 2 项

- ✅ **划词翻译流式输出**：Port（`it-stream`）+ provider SSE（openai/anthropic/gemini/ollama），rAF 节流逐字渲染，
  关闭气泡即中止（复用 signal 管线）；未产增量时按既有降级链回退。
- ✅ **iframe 支持**：manifest `all_frames`，子 frame 独立引擎/守卫/autoTranslate；Alt+T 经 tabs.sendMessage 广播。
  已知限制：工具条按钮暂不作用于子 frame（跨 frame 同步需 background 新消息，可作后续小项）。
- ✅ **Shadow DOM 提取**：open root 遍历 + adoptedStyleSheets 样式注入（按模式/主题直出）。已知限制：MutationObserver
  不观察 shadow 内部，动态 shadow 内容由下次全量/点击扫描覆盖。
- ✅ **站点规则库**（2026-09-14 落地）：`src/shared/siteRules.ts`——12 条内置规则（全局数学公式区 +
  GitHub/Discord/Reddit/YouTube/HN/StackOverflow/ChatGPT/Medium/Notion/Substack/Wikipedia 的排除区，
  选取原则「只排明确无翻译价值的区域」）+ 用户自定义 JSON 规则（每行一条或整段数组：
  excludeSelectors / excludeTags / forceBlockTags / excludeMatches / enabled）+ 设置页勾选禁用内置规则。
  域名通配（*.example.com、www.amazon.*）与路径前缀匹配；接入提取器（排除区子树/标签跳过、
  强制块级锚定）、Shadow DOM 宿主判定与属性翻译过滤；导入走 sanitizeSiteRules 逐字段校验（封顶 100 条）。
- ✅ **自定义翻译 prompt**：`api.customSystemPrompt` 附加指令注入（协议段强制保留），设置页 textarea。
- ✅ **悬停翻译**：块级元素「译」角标 + 单段翻译（`engine.translateElement`，页面状态钳制防整页补译）。
- **UI 英文化**：`src/content` 字符串收敛到 `src/shared/i18n.ts`（先中英双语），为上架做准备。**（未做）**

### P2：差异化大功能（按兴趣选做，每个都是独立里程碑）

- **YouTube 字幕翻译**：拦截 timedtext 请求拿原始字幕 → 分段 → 按播放时间轴预译 → 双语字幕覆盖 + SRT 导出。工程量大（平台适配 + main-world 拦截器 + 字幕渲染），但做完就是插件最亮的差异化点，read-frog 的实现可逐模块参考。
- ✅ **TTS 划词朗读**（2026-09-14 落地）：划词气泡「朗读」按钮 + Edge TTS 免费合成（HMAC 签名换端点令牌 →
  区域端点 POST SSML，`src/background/edgeTts.ts`）+ offscreen 文档播放（`public/offscreen.html/js` +
  `src/background/ttsPlayback.ts`）+ 失败熔断（5 次/10min → 开 15min）。声音按目标语言自动选（16 语言，
  可显式指定）、语速可调；关闭气泡即停。已知限制：单次合成上限 3000 字符（不分块续播）、无声音列表拉取。
- ✅ **LLM 上下文摘要**（2026-09-14 落地）：长文页（正文 ≥ `translate.summaryMinChars`，默认 6000，
  0 = 不限）整页翻译期间异步请 LLM 生成 2-3 句文章摘要注入上下文（`TranslateService.generatePageSummary`
  + `SummaryCache` 按页缓存，键掺通道格式/模型变体）。首批请求不等待（先带原文截断上下文），
  摘要返回后的批次自动携带；失败静默回退原文截断，免费通道自动跳过。默认关闭，设置页开启。
- **语言检测增强**：读取 `<html lang>` + 内容启发式 + 可配置「强制源语言」。

### P2：工程健壮性

- 站点规则回归测试：照 read-frog 用「保存真实站点 DOM 片段」的方式建 `tests/fixtures/`，防提取回归。
