> 日期：2026-09-14（当日完成 P0 一揽子后更新）

## 一、定位差异——先说清楚不追什么

read-frog 的定位是「AI 语言学习产品」：文章分析、词句讲解（CEFR 分级）、生词本（Notebase）、TTS 朗读、账号体系、数据分析。我们定位是「轻量纯翻译工具」。

**不学它的**：React/Jotai/TanStack 技术栈、monorepo/nx/changesets 工程链、账号与激活体系、行为分析、sidepanel。这些是团队产品化的配置，照搬只会丢掉我们「单文件、零依赖、秒加载」的差异化优势。我们的目标不是变成 read-frog，而是**把一个轻量翻译工具的核心体验做到不输它，同时保留它没有的轻量与可控**。

## 三、小而美的借鉴项（低成本，先做）

这些是 read-frog 里「几十行就能搬过来」的点子：

1. ✅ **缓存 TTL + 定期清理**（已完成，见 P0 一揽子）。
2. ✅ **批量超时按字符数缩放**（已完成：`base + 15ms × 字符数`，封顶 120s）。
3. ✅ **跨标签页请求去重**（已完成：文本+语言在途去重，等待者不随属主会话中止而失败）。
4. ✅ **巨型段落拆分**（已完成：提取阶段按句子边界均衡拆 chunk，中文句读必切、英文 `3.14`/`e.g` 不误切）。
5. ✅ **`{{NO_TRANSLATION_NEEDED}}` 哨兵**（已完成：LLM 批量免译显式回哨兵，解析严格相等映射回原文；免费通道解析兜底）。
6. ✅ **视口优先调度**（2026-09-14 落地）：`translateUnits` 内批次按「距视口距离」动态出队
   （每次出队前按当前视口重选最近的批，滚动后未发批次跟随用户位置），先完成的批先渲染
   （消除队头阻塞）；并发度仍由 FETCH_WINDOW 钳制。jsdom/rect 全 0 环境退化为 DOM 顺序。

### P2：差异化大功能（按兴趣选做，每个都是独立里程碑）

- **YouTube 字幕翻译**：拦截 timedtext 请求拿原始字幕 → 分段 → 按播放时间轴预译 → 双语字幕覆盖 + SRT 导出。工程量大（平台适配 + main-world 拦截器 + 字幕渲染），但做完就是插件最亮的差异化点，read-frog 的实现可逐模块参考。

  `src/background/ttsPlayback.ts`）+ 失败熔断（5 次/10min → 开 15min）。声音按目标语言自动选（16 语言，
  可显式指定）、语速可调；关闭气泡即停。已知限制：单次合成上限 3000 字符（不分块续播）、无声音列表拉取。
- ✅ **LLM 上下文摘要**（2026-09-14 落地）：长文页（正文 ≥ `translate.summaryMinChars`，默认 6000，

## 八、审查留观项（已知限制，暂不处理）

> 来自历轮代码审查（2026-09-14 ~ 09-18，报告原文见 git 历史：docs/代码审查报告.md 与仓库根 结论1/结论2/最终结论.md）。

- tokenrhythm CSRF 403：已确认非插件回归（服务端拦截扩展类请求），已搁置；如需支持再评估 `declarativeNetRequest` 剥头。
- Gemini key 在 URL query 会进中转日志（诊断已脱敏）；后续可改 `x-goog-api-key` 头。
- `tokenizeGlossary` 子串替换可能误伤大小写恰好组成的词（术语 "AI" 与 "SAID"），影响极小。
- 页面无可译内容时引擎 state 保持 off，工具条仍显示「翻译」（语义合理）。
- `acquireStartSlot` 令牌等待的 sleep 不检查会话 signal：Retry-After 冷却期间 abort 需等睡醒才生效（窗口极窄）。
- `translate.autoDetectSource` 为休眠设置（全工程零消费、UI 未暴露）；`toMicrosoftSourceLang` 缺 `mo` 变体（经归一不可达）。
- 拖动/吸附未做仿射反解：html 自身带 transform/zoom 的站点拖动位移有缩放误差（此类站点极少，初始落位正确）。
- content 侧设置均为装载时快照：会话中途改设置（站点规则/自动翻译等）需刷新生效（历史语义一致）。
- pendingTexts 跨批串扰与共享文本统计粒度小偏差：下一轮翻译自愈，彻底解决需引用计数，收益不匹配。
- 划词 caret 几何（`caretRangeFromPoint`）jsdom 无法覆盖，hoverIframe 用例走旧 fallback，需真实浏览器验证。
- 行内链接拆段降级路径会牺牲该句链接可点击性（宁失可点击，不出重复/中英夹碎），换序频率待线上观察。

### 2026-09-18 全仓库审查遗留（4 个 P0 已修并变异自证 6/6，以下为未修部分，详见 git 历史 结论2.md / 最终结论.md 第四节）

- **P1 渲染可逆性组**：嵌套单元快照与还原过滤基准取自不同时刻（还原重复追加/内层原文丢失）；`data-it-src`
  是永久过滤标记且无文本校验（站点改写已译容器后新文本永不重译）；虚拟列表复用节点残留 `data-it-src`/`data-it-inside`

### 2026-09-18 深夜 · 第五轮（全量 diff 复审 + 4 项修复）

第四轮改动入库前做了一轮人工全量复审（推演了 wildcardMatch 无回溯算法、v2/v1/明文三态判别、
401 短路与备用切换的交互），确认第四轮核心修复全部成立，无 P0/P1。本轮修掉复审发现的 4 项：

- **UI 保存路径与导入校验区间不一致**：第四轮给导入加了区间校验（如 `maxConcurrency: numOf(1, 10)`），
  但设置页保存仍只钳下限（并发可输 100）、超时完全无范围（可输 1 秒，低于导入下限 5 秒）——同字段两套规则。
  已把全部区间收敛为 `storage.ts` 导出的 **`SETTING_RANGES` 单一来源**，导入校验与 UI 保存钳制共用，
  UI 侧超时按「秒输入 → 落盘毫秒」用 `timeoutSeconds` 衍生区间。`p0Regression.test.ts` 加了区间契约用例
  （防有人只改一处，含「秒区间 × 1000 = 毫秒区间」的一致性断言）。
- **Edge TTS 令牌失效重发共用计时窗口**：`synthOnce` 原把首次请求与 401 后重发放在同一个
  `withRequestTimeout(30s)` 作用域——首次请求耗掉大半窗口后返回 401，重发只剩零头时间，
  一次可恢复的令牌失效被误报成超时。已改为重发**独立起算 30s**。顺带修了一个次生问题：
  `withRequestTimeout` 原来在 `signal.aborted` 时一律报超时，会吞掉同刻发生的业务错误
  （如响应格式无效）；现在只在收到 `AbortError`（fetch 对 abort 的真实反应）时才替换成超时文案。
  新增 3 个用例：挂起请求 30s 被打断（fake timers，注意 crypto.subtle 异步链在时钟推进中途
  才注册超时器，须分段推进）、HTTP 500 不被超时文案吞掉、401 前置等待 3s 后重发仍全窗口可用。
- **路径模式侧不解码百分号转义**：第四轮给 URL 侧加了 `pathnameForMatch`（解码 + 小写），
  但模式侧没解码——用户从地址栏复制 `a.com/%E6%96%87%E6%A1%A3` 这类编码模式永不命中
  （地址栏通常显示解码形态，此类输入真实存在）。两侧现已同口径解码比对；畸形转义（`%zz`）
  两侧都退回原样按字面比对。
- **zip.mjs mtime 检查的误报来源**：`git checkout`/切分支会把源码 mtime 刷新为当前时间，
  之后即使 dist 仍有效也会被「dist 早于源码」拦下。属保守方向的误报（多跑一次 build 无害），
  不改判定逻辑，只在报错信息里写明原因与处理方式，避免未来被当真 bug 排查。

`npm run lint` 0 问题。复审确认无误、维持留观的：`withRequestTimeout` 对「业务错误与 abort 同刻发生」
的归属仍按超时外的原始错误处理（现有语义可接受）；package-lock 净删 512 行是 npm 本机重生成清掉了
