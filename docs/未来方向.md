## 一、定位差异——先说清楚不追什么

read-frog 的定位是「AI 语言学习产品」：文章分析、词句讲解（CEFR 分级）、生词本（Notebase）、TTS 朗读、账号体系、数据分析。我们定位是「轻量纯翻译工具」。

**不学它的**：React/Jotai/TanStack 技术栈、monorepo/nx/changesets 工程链、账号与激活体系、行为分析、sidepanel。这些是团队产品化的配置，照搬只会丢掉我们「单文件、零依赖、秒加载」的差异化优势。我们的目标不是变成 read-frog，而是**把一个轻量翻译工具的核心体验做到不输它，同时保留它没有的轻量与可控**。

## 三、小而美的借鉴项（低成本，先做）

这些是 read-frog 里「几十行就能搬过来」的点子：

1. ✅ **缓存 TTL + 定期清理**（已完成，见 P0 一揽子）。
2. ✅ **批量超时按字符数缩放**（已完成：`base + 15ms × 字符数`，封顶 120s）。
3. ✅ **跨标签页请求去重**（已完成：文本+语言在途去重，等待者不随属主会话中止而失败）。
4. **巨型段落拆分**：超高段落（超出视口数倍）在提取阶段拆段，避免单批 1200 字符上限产生畸形 chunk。
5. **`{{NO_TRANSLATION_NEEDED}}` 哨兵**：批量里混入疑似目标语的段落时让模型显式回哨兵，而不是硬译（与现有 isTargetLanguage 启发式互补，减少无效翻译）。
6. **视口优先调度**：请求队列按「距视口距离」排序出队（我们按批次顺序），滚动跟读时首屏更快。

### P1：体验增强（1–2 个月节奏）

- **划词翻译流式输出**：background 建 port 流式转发 provider 流（openai/anthropic/gemini 均可开 stream），气泡逐字出——划词场景体感提升最大的一项。
- **iframe 支持**：webNavigation + scripting 向全 frame 注入，documentId 去重；黑名单/敏感页判断在 frame 内同样生效。
- **Shadow DOM 提取**：extractor 的 TreeWalker 扩展 shadow root（遍历时 `shadowRoot` 入栈），样式注入用 adoptedStyleSheets。
- **站点规则库**：内置常见站点适配（如 GitHub/Discord 的排除区），用户可按站点自定义「不翻译的 tag / 强制块级」。
- **自定义翻译 prompt**：设置页可编辑 system 模板（保留批量协议段），进阶用户刚需。
- **悬停翻译**：hover 段落出现「译」角标，点一下只译该段——read-frog 与沉浸式翻译都有，长页精准翻译高频。
- **UI 英文化**：`src/content` 字符串收敛到 `src/shared/i18n.ts`（先中英双语），为上架做准备。

### P2：差异化大功能（按兴趣选做，每个都是独立里程碑）

- **YouTube 字幕翻译**：拦截 timedtext 请求拿原始字幕 → 分段 → 按播放时间轴预译 → 双语字幕覆盖 + SRT 导出。工程量大（平台适配 + main-world 拦截器 + 字幕渲染），但做完就是插件最亮的差异化点，read-frog 的实现可逐模块参考。
- **TTS 划词朗读**：Edge TTS 免费无 key，background 合成 + offscreen 播放，先做划词气泡的「朗读」按钮。
- **LLM 上下文摘要**：正文摘要从「原文截断」升级为「LLM 生成的文章摘要」（IndexedDB 缓存、每页一次）——翻译质量在长文/专业页会有可感提升，代价是每页多一次请求（可只在字数超阈值时启用）。
- **语言检测增强**：读取 `<html lang>` + 内容启发式 + 可配置「强制源语言」。

### P2：工程健壮性

- 优先级请求队列（视口距离排序）。
- 站点规则回归测试：照 read-frog 用「保存真实站点 DOM 片段」的方式建 `tests/fixtures/`，防提取回归。
- e2e 冒烟：playwright 加载 `dist/` 走一遍翻译/还原/切模式（read-frog 也没有 e2e，我们规模小反而容易做）。
